# 4단계 지식화 — 미션 설계안 (검토용)

> **단순화 (기능 사다리):** 이 단계는 새 기능 하나에 집중한다. 배포 방식 판단(소유자·검토 주기는 항상 기록)과 팀장 승인, 한유진 책임은 뺐다. 이도윤·최재석은 시험 문항의 암묵지를 갖고 있어 남겼다. 아래 설계 중 이 부분은 현재 시나리오에 없다.

> 상태: 설계 확정, 구현 중. 시나리오 id(가칭) `s4-knowledge`

## 한 줄 요약

5단계에서 AI Agent에게 **주간 수율 보고**를 맡기려면, Agent가 읽을 **지식 패키지**가 필요하다:
항상 읽는 짧은 규칙(지침 파일), 절차(스킬), 깊은 참고(위키·카탈로그 링크).
사람 머릿속의 **암묵지**를 인터뷰로 꺼내고, 오래되거나 민감한 문서는 걸러내고,
**지식 시험(eval)** 으로 Agent가 실제로 맞게 답하는지 확인하며 고친다.

## 캠페인 안의 위치

- 0–3단계: 데이터를 찾고, 만들고, 통일하고, 쌓았다 → **4단계: 일하는 방법을 AI가 읽을 수 있게 한다**
- 0단계의 숨은 매크로 규칙, 1단계의 현장 기호·사후 기록 관행이 여기서 **지식**으로 돌아온다
- 결과물(지식 패키지)은 5단계 Agent의 시작 조건이 된다

## 학습 목표

1. 지식은 문서 더미가 아니다 — **현행·검증된 것만** 고르고, 오래된 문서와 민감 정보는 뺀다
2. 가장 중요한 지식은 문서에 없다 — **암묵지 인터뷰**로 꺼내고, 추측으로 채우지 않는다
3. 지식을 **층으로 나눈다**: 항상 지킬 짧은 규칙 / 반복 절차 / 깊은 참고 자료
4. 지식이 맞는지는 **시험(eval)으로 확인**한다 — 틀린 답의 원인을 찾아 지식을 고치고 다시 시험한다
5. 지식에도 **소유자·출처·검토 주기**가 있다 — 그래야 낡지 않는다

## Agent

| 역할 | 하는 일 |
|---|---|
| assistant (지식 작성) | 문서 조사, 지식 패키지 작성·배포 |
| evaluator (지식 시험) | 지식 패키지만 읽은 Agent로 시험 문항 8개를 풀게 하고 채점 |

## 업무 구조

```
단계 1  [inventory]  지식 출처 조사 — 공유 드라이브 312건      (assistant, 판단 1)
        [interview]  암묵지 인터뷰 — 박서준·최재석·이도윤       (나 — 메신저)
단계 2  [draft]      지식 패키지 작성 — 구조 + 넣을 지식        (assistant, 판단 2)
단계 3  [eval]       지식 시험 8문항                           (evaluator)  ↺ 실패하면 고치고 다시
단계 4  [publish]    지식 배포 — 소유자·출처·검토 주기          (assistant, 도구 승인 1)
        [approve]    팀장 확인                                 (나)
```

## 판단 지점

| 위치 | 장면 | 좋은 판단 | 그럴듯한 나쁜 판단 |
|---|---|---|---|
| inventory | 지식 후보 | 위키 표준·데이터 카탈로그·현행 SOP 3건·인터뷰 기록 | 공유 드라이브 312건 전부 (2019년 구 SOP·개인 평가 메모 포함) |
| draft | 구조 | 짧은 지침 + 주간 보고 스킬 + 위키 링크 | 전부 지침 파일 하나에 (2,400줄) / 위키 링크만 |
| draft | 넣을 지식 (복수) | 수율 정의·시각·LEGACY·숨은 계산 규칙·사후 기록·판단 가이드 | 구 SOP(2019), 개인 평가 메모, 확인 안 된 규칙을 AI가 추측으로 |
| eval | 시험 결과 | 틀린 문항의 원인(빠진 지식·충돌·묻힘)을 찾아 고치고 재시험 | 통과율 75%면 충분하다고 배포 |
| publish | 도구 승인 `knowledge.publish(…)` | 소유자·출처·검토 주기 기록, AI 읽기 전용 | 출처·날짜 없이 복사 |

## 지식 시험 (eval) — 이 미션의 핵심

evaluator가 **지식 패키지만 읽고** 8문항을 푼다. 문항마다 통과 조건은 패키지에 들어간 지식(플래그)으로 결정된다.

| # | 문항 | 통과하려면 | 실패 원인 예 |
|---|---|---|---|
| 1 | W46 검사 수율은 몇 %이고 어떻게 계산하나? | 수율 정의 | 구 SOP와 충돌 → "투입 대비"로 답함 |
| 2 | 11/10 이전 D07을 D07a로 분류해도 되나? | LEGACY 규칙 | 묻힘 (지침 2,400줄) |
| 3 | 로거 04:20 정지를 보고서에 어떻게 쓰나? | 시각 규칙 | 묻힘 |
| 4 | 주간 수율에 재작업 웨이퍼를 넣나? | 숨은 계산 규칙 (**인터뷰로 확인**) | 인터뷰 없이 AI가 추측 → 반대로 답함 |
| 5 | 야간조 13:20 기록 시각을 믿어도 되나? | 사후 기록 관행 (**인터뷰**) | 빠짐 |
| 6 | D07이 급증하면 무엇부터 보나? | 판단 가이드 (**인터뷰**) | 빠짐 / '규칙'으로 단정 |
| 7 | 작업자 W-02의 성과는 어떤가? | **답하지 않아야 통과** | 개인 평가 메모가 들어감 |
| 8 | 이 데이터는 어디서 조회하나? | 데이터 카탈로그 링크 | 위키 링크 없음 |

시험 리포트는 문항별 통과/실패와 **실패 원인**을 보여준다 (`sim://work/eval`). 플레이어는 원인에 맞게 고친다:
빠진 지식 → 인터뷰, 충돌 → 구 문서 제외, 묻힘 → 구조 변경, 민감 정보 → 제거.

## 이월 효과

| 앞 단계 | 4단계에서 |
|---|---|
| 0단계 매크로 규칙 발견 (`found.macro`) | 인벤토리에서 인터뷰 기록 발견 — 박서준 선임을 다시 설득할 필요 없음 |
| 0단계에서 박서준 선임 신뢰 낮음 | 숨은 규칙을 털어놓지 않음 (minTrust) — 먼저 안심시켜야 함 |
| 1단계 현장 기호·사후 기록 | 문항 5의 근거 |
| 3단계 데이터 카탈로그 | 문항 8의 근거 (없으면 실패) |
| 3단계 AI 권한 (`access.ai.mart_ro`) | 지식 패키지의 "데이터는 여기서 조회" 규칙이 실제로 동작 |
