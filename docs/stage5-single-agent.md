# 5단계 단일 Agent 활용 — 미션 설계안 (검토용)

> 상태: 설계 확정, 구현 중. 시나리오 id(가칭) `s5-single-agent`

## 한 줄 요약

4단계 지식 패키지를 읽는 **주간 보고 Agent 하나**에게 실제로 보고를 맡긴다.
잘 위임하고(브리프·계획 확인·권한), 결과를 검증하고(마트와 대조), 틀린 것을 고친다.
핵심은 **결과물만 고치지 말고 시스템(지식 패키지)을 고치는 것** — 그래서 **두 주(W51 → W52)** 를 연달아 맡긴다.
W51에서 보고서만 고친 실수는 W52에 그대로 다시 나온다.

## 캠페인 안의 위치

- 0–4단계: AI가 일할 수 있는 기반(데이터·표준·마트·지식)을 만들었다 → **5단계: 처음으로 일을 맡긴다**
- 4단계 지식 시험에서 놓친 문항은 여기서 **실제 보고서의 오류**로 나타난다
- 플레이어 역할이 **리더**로 바뀐다: 직접 하지 않고, 맡기고 검증하고 시스템을 개선한다
- 6단계(Agent 설계)로 넘어가는 질문: "앞으로 이 업무를 어떻게 운영할까?"

## 학습 목표

1. 위임은 **브리프**로 한다 — 목표·맥락·제약·완료 기준·모를 때의 행동
2. 실행 전에 **계획을 확인**하고, 되돌리기 어려운 행동(팀 채널 게시)은 **승인 전에 막는다**
3. Agent의 "완료"를 믿지 말고 **원천(마트)과 대조**해 검증한다
4. Agent가 **모르는 상황**(새 설비)과 **과신**(원인 단정)을 구분해 잡는다
5. 오류는 결과물이 아니라 **지식 패키지에 반영**해 다음에 반복되지 않게 한다
6. 업무 운영 방식을 정한다 — AI 초안 → 사람 검토 → 지식 개선 루프

```
W51  [w51]        주간 보고 W51 작성          (report-agent — 브리프 · plan mode · 게시 승인)

```

## 브리프 (프롬프트 조건)

지시 카드의 조건이 곧 브리프다.

| 조건 | 효과 |
|---|---|
| 지식 패키지(AGENTS.md · 주간 보고 스킬)를 따를 것 | 기본 — 없으면 지식을 안 읽고 일반 관행으로 씀 |
| 확실하지 않은 건 '확인 필요'로 표시 | 새 설비 ET12를 **추측해 매핑하지 않고** 표시 |
| 숫자마다 출처(마트 뷰·쿼리)를 남길 것 | 검증이 쉬워짐 (대조 시간 단축) |
| 원인은 단정하지 말고 가설로 | 원인 과신 방지 |
| 초안까지만 — 게시는 내가 | 게시 도구 승인 요청이 아예 안 나옴 |
| ✗ 알아서 완벽하게 / 빨리 끝내고 팀 채널에 바로 올려 | 그럴듯한 나쁜 조건 |

## W51 보고서에 숨은 오류

| 오류 | 언제 생기나 | 어떻게 잡나 |
|---|---|---|
| 새 설비 **ET12**를 ETCH-01로 추측 매핑 | 항상 (지식에 없는 상황) — 브리프에 '확인 필요' 조건이 없으면 추측 | 보고서 열기 → 오태식 파트장에게 확인 → 수정 지시 |
| D07 증가 원인을 **"CMP 슬러리"로 단정** | 브리프에 '가설로' 조건이 없고 4단계 판단 가이드가 약하면 | 이도윤 엔지니어에게 확인 → 수정 지시 |
| 검사 수율에 **재작업 웨이퍼 포함** (0.6%p 차이) | 4단계 시험 4번 실패를 그대로 넘겼으면 | 보고서와 마트 뷰(`sim://mart/yield`) 대조 |
| **작업자 메모** 포함 | 4단계에서 회의록이 섞였으면 | 보고서 열기 |
| 시각이 UTC 그대로 | 4단계 시험 3번 실패 | 보고서 열기 |
| 숫자에 출처 없음 | 브리프에 '출처' 조건이 없으면 | 검증이 오래 걸림 (평가 반영) |

수정 지시 선택지는 **보고서나 마트를 직접 열어본 뒤에만** 나타난다 (기존 '화면 확인 후 버그 지적' 방식).
각 수정 지시에는 "이번 보고서만" / "**지식 패키지에도 반영**"이 있다.

## W52 — 루프가 닫혔는지 확인

W52는 같은 브리프로 다시 맡긴다. W51에서 **지식 패키지에 반영한 오류만** 사라진다.
보고서만 고친 오류는 W52에 그대로 다시 나오고, 플레이어는 그걸 보고 시스템을 고쳐야 했다는 걸 체감한다.

## 판단 지점 (도구 승인·계획)

| 위치 | 장면 | 좋은 판단 | 나쁜 판단 |
|---|---|---|---|
| w51 계획 | plan mode에서 계획 확인 | 계획 승인 (또는 위험한 단계가 있으면 반려) | plan mode 없이 바로 실행 (나쁜 건 아님, 평가에서 긍정 요소만 없음) |
| w51 게시 | 도구 승인 `send_message(channel: 수율팀 전체, file: weekly_W51.md)` | 거절 — 검토 후 게시 | 승인 (검토 전 게시 → 틀린 숫자가 팀에 퍼짐, 팀장 신뢰 하락) |
| operate | 운영 방식 | AI 초안 → 박서준 선임 검토 → 게시, 오류는 지식에 반영 | AI 자동 게시 / 다시 사람이 직접 |
